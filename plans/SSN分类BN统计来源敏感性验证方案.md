## 三、单一干预的精确定义

### 3.1 目标模块（已只读核对源码）

`Discriminator.dec_head` 由 `_conv_block` 构造，为 `nn.Sequential(Conv2d, BatchNorm2d, ReLU)`，因此 `model.discriminator.dec_head[1]` 是：

- 类型 `nn.BatchNorm2d(128)`
- `affine=True`（γ=weight、β=bias，形状(128,)）
- `eps=1e-5`（构造未传参，取默认值）
- `track_running_stats=True`，`momentum=0.1`
- 输入张量形状 `(1, 128, 160, 58)`：`dec_head` 为5×5卷积、`padding="same"`，特征网格160×58在卷积后保持不变

**第1阶段必须以冻结源码与实际加载后的模块属性复核以上五项**；任一项不符（例如affine为假、输入非4D、eps不同）则停止并另写修订，不在本方案内静默替换。

### 3.2 原始行为与干预行为

- 原始（eval）：`y = (x − running_mean)/sqrt(running_var + ε)·γ + β`
- 干预：按通道使用**当前单图**统计
  - `μ_c = (1/(N·H·W))·Σ x`
  - `σ²_c = (1/(N·H·W))·Σ (x−μ_c)²`，**有偏方差**（分母为样本数），对齐BatchNorm训练模式的归一化方差，不用无偏估计
  - `y = (x − μ_c)/sqrt(σ²_c + ε)·γ + β`
  - 当 N=1、H=160、W=58 时，每通道统计位置数为9280
- 不变：γ、β、ε、`num_batches_tracked`、所有参数、所有缓冲、其它所有模块

**必须写明的解释限制**：对5张异常图而言，"当前统计"由含缺陷像素的图自身计算，与16张正常图的统计含义不同。因此本干预同时包含"避开陈旧的running统计"与"随图内容自适应"两个成分，本设计**无法分离**；报告中不得把观察到的差异单独归因于前者。本干预是**推理期**统计来源敏感性，不构成训练期BN效应证据。

### 3.3 实现路径（唯一路径，不设并列备选）

**采用torch原生核函数的"无缓冲批统计"调用**：在干预作用域内把`dec_head[1].forward`临时替换为单一原生调用

```
y = F.batch_norm(x, None, None, module.weight, module.bias,
                 training=True, momentum=0.0, eps=module.eps)
```

随后在`finally`恢复原`forward`。三点必须写清：

- `training=True`在这里只表示"用当前输入统计而非缓冲"；因为`running_mean`／`running_var`都传`None`，**不产生也不写任何缓冲**，`num_batches_tracked`不变，`state_dict`前后hash天然一致
- 统计量由torch原生核函数计算（有偏方差、`eps`位置与BN训练模式一致），**不是手写的`x.mean/var`**；这避免float32累加路径差异混入干预差异
- **不得改用"置`track_running_stats=False`"**：该模块的缓冲在构造时已注册。eval下`bn_training`判为假，而`forward`内的传参条件`not self.training or self.track_running_stats`因`not self.training`为真而短路，running统计**仍被照常传入**——因此该切换是一次**静默无操作**，行为与原模型逐位相同，恰好落进3.4要防的假阴性（不是报错，反而更隐蔽）。也不得把`running_mean`／`running_var`置`None`，那等于写缓冲

其余边界：

- 不调用`module.train()`、不改`momentum`、不更新`running_mean`／`running_var`
- 替换函数须以**闭包绑定`module`本身**（实例属性上的普通函数不会自动获得`self`）；恢复时用`del instance.forward`让类方法重新生效，或回填已保存的原bound method，二者择一并由第2阶段AST核验固定
- `discriminator.seg`与`feature_extractor`保持`eval`与原前向，不设任何替换
- 不修改`core_v1_dtype_compat`任何文件；干预写在新建的诊断模块内
- 不改变输入、预处理、sigmoid、fc、阈值
- 收尾须核验`state_dict`hash等于`1513a3df…`、`dec_head[1].training is False`、原`forward`已恢复

**语义核验（独立小步骤第1b）**：用独立`nn.BatchNorm2d`实例与合成张量在CPU**于`torch.inference_mode()`内**执行（匹配第3阶段语境），比较上述原生调用与float64参考公式（有偏方差、同`eps`），最大绝对误差须≤1e-5；同时断言`weight`／`bias`均非`None`，并核验调用前后该实例的`running_mean`／`running_var`／`num_batches_tracked`逐位不变。该步骤需导入CPU-only Torch，**须用户单独授权**；未获授权则第1阶段不含此核验，且第3阶段不得启动。核验不通过则停止修订，**不得**改用手写实现顶替。

### 3.4 补丁生效断言与统计差异记录（防假阴性）

若干预实际未生效，输出将与基线逐位相同并被误读为"不敏感"。因此每图前向后必须同时通过以下四项，任一项不满足立即停止、该次运行作废、不得进入判读：

1. 生效计数`patch_invocations`逐图递增，收尾须等于21；`patch_restorations`同样等于21
2. 逐图记录`max_c|μ_current − running_mean|`与`max_c|σ²_current/running_var − 1|`，两者须**先判有限**（`running_var`为0时比值会成inf并平凡通过），再判>1e-6（机器精度量级的底线，实际差异通常远大于此）；同时记录`median_c`与取到最大值的通道号
3. 同图记录：`dec_head[1].training`仍为`False`、替换与恢复各发生一次、实际走的是原生`F.batch_norm`路径（由包装内计数器证明），而非未生效的原方法
4. 若四项全过而该图`Δlogit`恰为`0.0`，须在报告中单列，不得直接当作"不敏感"证据

第1项与第2项不可互相替代：计数只证明代码跑了，统计差异才证明两个臂真的不同。

### 3.5 为什么这一层是唯一被选的

它位于专门分类路径（`dec_head(cat(cls_feat, map))`→`dec_max/dec_avg`→`fc_score`），可观察分类分数变化；同时分割输出`map`不被其回写，可作为未受干预的内部控制。选择它只表示"最小可检验"，不表示已认定其为根因，也不排除其他层。

## 六、事务、失败与恢复

1. 任何Torch导入、模型构造、权重加载之前写`transaction.json`；未写事务即发生的模型操作视为无效运行。
2. 失败（非有限、控制超差、身份不符、RAM越界、异常）→ 写`failure.json`，**保留全部已完成`npz`与部分输出**，不删除、不补推、不自动重试、不删除锁或游标。
3. 目标目录已存在且无`complete.json` → 停止并查因，不覆盖、不续写。
4. 本诊断是单次21前向任务，**不设断点续跑**；中断后若需重跑，必须由用户显式以新run名授权，并保留旧现场。
5. 成功路径：先写`scores.json`／`control.json`／`identity.json`，seal目录，最后写`complete.json`。顺序不可颠倒。
6. 完整缓存再次执行只做只读核验与复用，新增前向必须为0。

## 八、预注册判读规则

本节在运行前冻结，运行后不得按结果调整。

**选行规则（按序判断，先命中者生效）**：①控制失败→停止；②3.4四项断言任一失败→运行作废；③否则看**决策翻转张数**（严格`sigmoid>0.5`的翻转数）；④翻转>0→行A；⑤翻转=0且`max|Δlogit|>1e-6`→行B；⑥翻转=0且`max|Δlogit|≤1e-6`→行C。Δlogit／Δsigmoid只作描述，不参与选行。

| C | 控制通过，翻转=0，`max abs(Δlogit)`≤1e-6 | 统计与决策均无实质变化：该池对该层统计来源**不敏感** | 不得反证"BN必然无关"，只否定该层作为本池主因的必要性 |
| 附记 | FP降至≤1/16（可与A／B／C同时成立） | 仅记录：本池在该干预下计数改善 | 不得写"已验证修复"、不得改原`gate=false`、不得进入正式实验 |
| 附记 | FP不变或增加 | 完整保留负结果 | 不得切换第二因素（如seg BN）或增加重复次数救结果 |

数值地板`1e-6`在协议中冻结，约为基线logit／sigmoid自洽误差4.29e-8的23倍余量。**但须写明其局限**：两臂分别走BN的训练核与eval核，`Δlogit`必然包含无法分离的核算术差异，故`1e-6`不是噪声校正后的显著界，只是"是否值得描述"的约定；`C`行在实践中可能为空，此时按`B`行如实记录，不得为凑出`C`行而调整地板。真正判断"干预是否改变了统计"依据3.4第2项，而非`Δlogit`。"跨零"一律由strict `sigmoid>0.5`判定，不由logit符号反推。不设"显著／不显著"的二值统计裁定：本设计只有21张图、无重复，结论只落在上表允许表述内，并注明这些是训练同池描述量。

**描述性主量：边界间隔**M = min(R5 logit) − max(N16 logit)。基线M=1.098185（12245=1.705503，12025=0.607318），须报告新M与ΔM。补充事实：10个FP中最小logit为0.027133（11145），只占间隔的**2.5%**；12025为0.607318，占**55.3%**。清掉11145只需再下移0.027，清掉12025则还需额外0.580；同时12245的裕度只有1.706。因此计数变化大概率由这两张边界图主导，报告须直接说明。（旧版"约3.3倍间隔"无明确定义，已删。）M不构成AP／AUROC，也不作显著性检验。

**控制失败的分诊（R5）**：控制失败即停止，本方案**不包含**"额外补跑1次未改造基线"的复现探针。若届时需要区分"数值噪声"与"干预泄漏"，该探针须由用户单独授权、另立步骤并独立记录前向数，不得在本方案内自动追加，也不得因此重跑21次中的任何一张。
