# 第一周计划：按 Skills 逐步完成公开调研

修订日期：2026年10月9日。执行环境：私人设备。只使用公开资料，保持公司材料隔离。

## 目标与执行方式

本周交付一份中文初步调研报告，包含研究方向、选题依据和第二周的最小实验方案。

用superpowers:writing-plans的任务分解方式安排顺序、输入、输出和完成条件；阅读、检索与写作分别交给专业skill。按照你的要求，不设置过程表格、每日记录或逐项留痕要求，也不套用软件开发的测试、提交流程。

每天按下面的顺序推进。可以直接把每一步的指令发到当前聊天，让我执行；也可以自己阅读，再让我帮助解读。每步得到的有用内容汇入同一份主报告；已有三篇的专题解读作为参考材料保留，不增加过程表。

当前重点解读与选题、实验方案已写入[主报告](D:/华兴源创/报告/显示屏缺陷检测调研报告.md)：第8–10节为检测基线与增强，第11–14节为生成对比与候选问题，第15节为第二周方案。第一周尚可按第5天第二步整理报告；设备确认与运行条件实测放在[第二周执行计划](D:/华兴源创/计划/第二周执行计划.md)第1天完成，完整资源核验尚未全部完成。

## Skills 分工

| Skill | 本周用途 |
|---|---|
| superpowers:writing-plans | 拆解任务、收敛方向、组织可执行的最小实验方案 |
| nature-reader | 依据原文重点解读与对比论文，解释关键流程和实验 |
| nature-academic-search | 核验引文，补充确实缺少的文献，核对官方公开资源 |
| nature-writing | 按主题组织中文调研报告，让结论对应已有证据 |

阅读采用你已选择的“重点解读与对比”，不是默认的全文双语翻译。写作采用中文调研报告形式，范围与证据以本项目为准，保留公开数据与真实屏幕验证的区别。

## 第1天：建立屏幕检测的整体认识

**Skill：nature-reader。**

输入：S01屏幕检测综述和S08工业图像异常检测综述。论文入口见[补充文献清单](D:/华兴源创/文献/补充文献清单与阅读路线.md)。

执行：
1. 从原文了解主要缺陷、检测流程与方法分类。
2. 区分点亮画面检测、外观检测、监督检测和正常样本异常检测。
3. 解释弱对比度、背景不均、摩尔纹与数据不足等问题。
4. 将屏幕专门结论与通用工业结论分开。

得到的结果：报告的“检测任务、方法和难点”部分。能回答屏幕检测关注什么、怎样做、为什么难，即可继续。

可直接发送：

> 用 $nature-reader 重点解读补充清单中的S01和S08，围绕显示屏缺陷检测解释缺陷分类、检测流程、方法分类与主要难点。结合原文说明屏幕研究和通用工业研究的区别。输出中文重点解读，用于最终调研报告；不做全文翻译，不建立阅读卡或过程表，重要结论注明原文定位或官方来源。

## 第2天：理解一个检测基线和增强路线

**Skill：nature-reader。依赖：第1天的任务框架。**

输入：S09 PatchCore和S03分段Gamma校正的Mura检测方法。

执行：
1. 解读PatchCore的正常样本、局部特征、记忆库和异常图流程。
2. 解读S03增强什么信号、怎样结合检测、实验怎样评价。
3. 比较两种方法的数据条件、输出、计算和潜在局限。
4. 讨论弱缺陷增强是否可能同时放大正常背景噪声；将尚未验证的判断标为假设。

得到的结果：报告的“基线与候选改进方法”部分。能解释一个基线及一个可验证的改进因素，即可继续。

可直接发送：

> 用 $nature-reader 重点解读S09 PatchCore和S03低对比度Mura检测论文，解释方法流程、数据条件、关键实验及局限，比较正常样本检测与图像增强的作用。帮助判断哪一种适合私人设备上的公开demo。只做中文重点解读，不写过程记录，不把通用数据结果当成屏幕效果；设备条件未知时明确说明。

## 第3天：比较屏幕缺陷生成与已有三篇

**Skill：nature-reader。依赖：前两天的检测与评价认识。**

输入：S06屏幕缺陷合成综述、S07 Assigned MURA扩散生成；已有个性化生成综述、SeaS、MAGIC的解读和原文。

执行：
1. 优先复用已有三篇笔记，必要时回看原文。
2. 比较屏幕专门方法与通用工业生成的数据要求、位置/类别/强度控制、正常背景保留和掩码。
3. 分清生成视觉质量、下游检测收益和对抗训练的不同目标。
4. 提出1—2个值得继续、可以用公开资源验证的具体问题。

得到的结果：报告的“生成方向与研究问题”部分。能说明生成方向解决什么、还需验证什么；不必这一天训练扩散模型。

可直接发送：

> 用 $nature-reader 重点解读S06和S07，并结合已有三篇文献笔记比较SeaS、MAGIC与屏幕专门生成方法。重点解释少样本条件、背景保留、缺陷位置/强度控制、掩码和下游评价，提出适合私人设备公开研究的1—2个问题。复用已有解读，重要判断回到原文；不做全文翻译，不增加过程文件，也不预设必须做对抗训练。

## 第4天：核验公开资源，确认下一周能做什么

**Skill：nature-academic-search。依赖：第3天提出的候选问题。**

输入：已有文献清单、候选问题、官方数据与代码页面。结合私人设备实际条件判断，设备信息可以用文字说明，无需填写清单或提交截图。

执行：
1. 核对相关论文的版本、发表类型及关键引用。
2. 若阅读发现缺口，再补最多2—3篇相关文献，避免重新扩展整套清单。
3. 从论文/作者/官方页面检查公开屏幕数据的获取、标注与使用条件。
4. 核对MVTec AD作为流程数据、PatchCore作为基线的官方来源及运行条件。数据和代码说明通过现有浏览工具核对，skill不保证自动运行代码。
5. 屏幕数据未获得时，明确采用公开工业流程验证与独立模拟敏感度研究的组合；不以公司材料补缺口。

得到的结果：报告的“公开资源与可行性”部分。确定一套首选组合和必要的替代路径，区分页面可访问、资源可获取和实际已跑通。

可直接发送：

> 用 $nature-academic-search 围绕前面候选问题核验已有引用，缺口明确时补最多2—3篇。结合官方页面检查公开屏幕数据、MVTec AD和PatchCore的来源、获取条件、标注、许可与运行要求。已有清单尽量复用，优先官方和作者来源。只输出对选题有用的结论与链接，不建过程表、不重新生成整套文献库；兼容性和运行情况没有实测就标为待验证。

## 第5天：先收敛实验，再整合最终报告

### 第一步：选方向，写最小实验

**Skill：superpowers:writing-plans。依赖：前四天的解读与资源结论。**

执行：选择一个主方向，必要时留一个备选；固定数据来源、基线、一个研究变量、对照和评价方法。实验步骤能顺序执行，条件不满足时有替代方案。仅规划第二周实验，实际安装、下载和训练由后续执行任务处理。

得到的结果：报告中的“建议研究方向与最小实验”。

可直接发送：

> 用 $superpowers:writing-plans 根据前面的公开调研和可行性结论，帮我选择一个主方向和一个必要备选，并规划第二周最小demo。写清数据、基线、一个改进因素、对照、划分、指标和执行顺序。设备信息不足时给有条件的方案。这里只写研究实验计划，不执行开发，不设置勾选追踪、过程表、测试或提交流程；把方案作为最终报告的一部分。

### 第二步：整合报告

**Skill：nature-writing。依赖：上一步的选题与实验方案。**

执行：按“任务与难点—方法与研究方向—证据与局限—选题依据—实验方案”组织内容。报告的主张是公开研究梳理与待验证的实验建议，不声称已经取得检测提升；第一周的写作不要求新增实验数据。

最终文件：[显示屏缺陷检测调研报告.md](D:/华兴源创/报告/显示屏缺陷检测调研报告.md)。该文件已有前三天阅读内容；整合写作时复用已有内容，补充资源结论和最终方案，调整为完整报告。

可直接发送：

> 用 $nature-writing 将前面已完成的公开文献解读、资源核验和最小实验方案整合成中文初步调研报告，保存到 D:/华兴源创/报告/显示屏缺陷检测调研报告.md。面向实习带教工程师，按问题和方法组织，不逐篇复述摘要。写清建议方向、依据、实验方案和局限，引用已核验来源；未执行的实验全部写成计划，不虚构结果。只交付这份报告，不新增过程表或管理文件。

报告能让读者理解主要问题、相关研究、建议方向和下一周怎样验证，就达到本周目标。重要论文判断有来源，实验方案可以执行，结论边界明确；阅读数量和过程记录不作为成果质量的替代标准。
