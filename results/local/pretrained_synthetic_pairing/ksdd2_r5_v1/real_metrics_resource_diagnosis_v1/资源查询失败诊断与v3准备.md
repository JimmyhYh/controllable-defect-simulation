# 第6阶段精确AP资源查询失败诊断与独立修复

原因已经通过独立CPU进程复现：pretrained_synthetic_pairing.common.resource_snapshot给共享ctypes.windll.kernel32.GlobalMemoryStatusEx设置POINTER(Memory)，fewshot_synthetic.data.available_ram随后传入另一类型M的指针，触发参数类型错误。失败时保存可用RAM约7.169GiB，不是RAM不足；这里是包装层兼容错误，不能据此判断模型检测效果。
